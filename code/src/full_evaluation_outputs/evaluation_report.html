    §1Executive summary

    The pipeline evaluated cleanly end-to-end on real data. The headline numbers are mixed news for the comparative model, and the calibration check — the load-bearing premise of this whole research option — passes with a genuine, verified signal.

    Segmentation

    Baseline outperforms comparative on raw overlap — mean foreground Dice 0.757 vs. 0.711 — and far more on topology: comparative's Euler characteristic difference is 5–6× worse on White Matter and Brainstem specifically, despite similar Dice on those classes. See §4–5.

    Calibration

    Passes, with a real and verified signal (Spearman ρ = 0.400, p ≈ 0, n = 16.8M voxels) — but not from the model's own uncertainty head. That head is provably untrained; the evaluation script substitutes softmax predictive entropy, and I confirmed by direct measurement that this substitute correlates with real error roughly 5–6× better than the trained head does. See §6.

    Data

    Three test cases (sub-017, sub-020, sub-025) collapse on both models — eCSF/GM/Cerebellum/Brainstem Dice as low as 0.00–0.19, while every other case scores 0.68+. This single-handedly drags down several class means and is reproducible across two independently-trained checkpoints. See §8.

    §2How the evaluation pipeline works

    src/evaluation/full_evaluation.py is a single consolidated script (merged from six earlier modules) built around one idea: it never imports a concrete model class. Instead it defines a structural typing.Protocol — SegmentationModel for the baseline, UncertaintyModel for the comparative model — and both real checkpoints are wrapped in a thin adapter that satisfies it. That's what let this evaluation code be written, tested, and verified before either real checkpoint existed, and run unmodified once they did.

    Model correctness checks, before trusting any number

    Before running the real evaluation, both checkpoints were verified directly, not assumed:

    • Strict weight loading — load_state_dict(..., strict=True) for both BaselineUNet (22.6M params) and UncertaintyUNet (22.6M + a small uncertainty head): all keys matched exactly.
    • Non-degeneracy check — both models predict all 8 real tissue classes with sensible voxel counts on real in-distribution data (not the single-class collapse seen when the baseline checkpoint was earlier fed out-of-distribution synthetic data as a sanity test).
    • Cross-model agreement — baseline and comparative agree with each other on 95.0% of voxels on a sample patch, and each agrees with ground truth on ~89%, consistent with two independently-trained models sharing the same task and backbone.

    Speed: what actually helped

    This ran on a 4-core CPU laptop, no GPU — full 128³ sliding-window inference for both models across 12 cases is fundamentally compute-bound. Before touching the script, I benchmarked four candidate speedups; only one helped:

    LeverResultUsed?
    Batching multiple tiles per forward call44.6s/patch vs. 15.1s/patch looped — slowerNo
    Thread count 4 → 8 (this CPU has 4 physical cores)14.0s vs. 14.3s — no changeNo
    Conv+BatchNorm fusion (mathematically exact in eval mode)16.35s vs. 16.46s — no changeNo
    Tile stride 50%→100% overlap (full coverage either way)129 → 88 tiles across the 12 casesYes

    The reason: a volume between 1×–2× the patch size needs exactly 2 tiles per axis regardless of stride — overlap there is unavoidable. But several test cases (e.g. sub-054 at 204×247×195) needed 3 tiles per axis under 50% overlap; raising the stride to 100% (no intentional overlap, full voxel coverage unchanged) cut that back down to 2 per axis. Net effect: this run finished in 47.0 minutes instead of an estimated ~56.

    §3What's being measured

    MetricWhat it answersComputed by
    DiceOf the voxels a class should occupy, how many did the model get right? (0–1, higher better)dice_per_class, mean_dice
    Euler char. diff. (ED)How many extra/missing holes or disconnected blobs does the prediction have vs. ground truth? Catches anatomically implausible shapes Dice can miss.euler_characteristic_difference
    Calibration (Spearman ρ)Does the model's predicted uncertainty actually track where it's wrong? Gate: ρ>0.2 and p<0.05.compute_calibration_summary
    Refinement Δ (Dice/ED)Does the rule-based, uncertainty-guided boundary refinement step actually improve eCSF/GM/dGM?compare_before_after_refinement

    Mean Dice excludes background (class 0) by default — it dominates volume and is trivially easy, so folding it in would mask the foreground performance this evaluation actually cares about. ED uses 6-connectivity, applied identically to prediction and ground truth.

    §6Calibration — does predicted uncertainty track real error?

    This is the load-bearing check for the whole research option: if uncertainty doesn't correlate with real error, the refinement step in §7 has nothing real to act on. It passes — Spearman ρ = 0.400 (p ≈ 0, n = 16,832,053 voxels), comfortably past the ρ>0.2, p<0.05 gate.

    But

    That signal isn't coming from UncertaintyUNet's own dedicated uncertainty head. I traced why and verified it directly rather than assuming:

    1. The uncertainty head is provably untrained. training/train_comparative.py has a genuinely correct heteroscedastic loss — it interprets the head's output as log-variance and computes a proper negative-log-likelihood term against per-voxel cross-entropy. But uncertainty_loss_weight: 0.0 in the only training config in the repo multiplies that entire term by zero. The head's weights confirm it: std 0.0999, statistically indistinguishable from a fresh random init (0.111), versus the actually-trained segmentation head's 0.131.

    2. Even the fallback MC-dropout route is dead code. UncertaintyUNet declares self.mc_dropout but its forward() never calls it — confirmed by running two "stochastic" forward passes on identical input and getting bit-identical output.

    Measured directly: the raw uncertainty head correlates with real voxel error at ρ = 0.063 (barely above noise). The evaluation script's fallback — plain single-pass softmax predictive entropy — correlates at ρ = 0.335–0.400. That's why full_evaluation.py uses the fallback: it's not a stopgap, it's measurably the better signal available on this checkpoint.

    §7Before/after refinement — eCSF, GM, dGM

    Given calibration passes, does the rule-based refinement step (reassign high-uncertainty boundary voxels to their local-majority class) actually help? Barely, either way. Changes are close to flat — a fraction of a Dice point in either direction.

    Why so flat

    refinement_threshold = 0.5 is a placeholder — Role 4 hasn't tuned it against the validation split yet, so this isn't evidence refinement doesn't work, only that this specific untuned threshold barely triggers. Re-run once a real threshold is selected before drawing conclusions either way.

    §8Three cases collapse on both models

    sub-017, sub-020, and sub-025 score dramatically worse than every other test case on eCSF, GM, Cerebellum, and Brainstem — on both independently-trained checkpoints. Comparative's Brainstem Dice on two of them is exactly 0.000.

    This is the same "simultaneous small-structure depletion" pattern qc_and_split.py's own docstring used to justify excluding one case (sub-022) during QC. Since it's reproducible across two separately-trained models, it's more likely a genuine property of these three cases (very early gestational age? a preprocessing edge case?) than a fluke of either model — worth a direct look at the source volumes before trusting the pooled per-class means at face value.

    §9Open questions & recommendations

    1. Fair-comparison audit. Comparative trained for 42 epochs (early-stopped, best val Dice ≈0.732 at epoch 32 — checkpoints_comparative/comparative_history.json). No equivalent history file exists for baseline anywhere in the repo, so whether both models trained under the same epoch/optimizer budget — required for a clean ablation — is currently unverifiable. Ask Role 2 for their log.
    2. Fix the uncertainty head, then retrain. Set uncertainty_loss_weight to a nonzero value in the training config and wire self.mc_dropout into forward(). The loss formula in train_comparative.py is already correct — it just never ran with a nonzero weight.
    3. Tune the refinement threshold on the validation split (never test) before treating §7's near-flat result as final.
    4. Investigate the 3 outlier cases directly (§8) — check gestational-age proxies, raw volumes, and QC logs for sub-017/sub-020/sub-025.
    5. Investigate the WM/Brainstem topology regression (§5) specifically — it's large, consistent, and currently unexplained; likely worth a slice-level look (Role 6's territory) at what comparative's WM/Brainstem predictions actually look like on a mid-range case.
